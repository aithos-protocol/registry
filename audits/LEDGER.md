# Audit ledger

One line per finding that was acted on, so that a later round cannot quietly
undo an earlier decision. Read before applying any fix.

Auditors do **not** see this file. They work blind, from the code alone, so
their findings stay independent; this ledger is how the person applying the
fixes checks a new finding against what was already decided and why.

Rounds 4 through 8 were each cleaning up after the previous round. That is not a
loop — no decision was ever reversed, and `LEDGER.md` was checked before every
fix — but it is the shape a loop starts as, and it had one cause: **a new
component (the read-path sweeper) was introduced late, and each round found the
next layer of it.**

Two things ended it. Round 5 stopped patching the component and changed its
shape: the stream became a *trigger* rather than a second source of truth, so
one convergence rule serves both writers. And from round 6 every fix to that
component shipped with the test that would have caught the defect the fix was
correcting — which is how round 7's finding was pinned, and why rounds 9 and 10
found nothing there.

Three findings were **declined** rather than fixed, and each is recorded above
with its reasoning so a later round does not re-raise it as new: ES256 low-S
enforcement (round 2, A-m4 — interoperability cost with no gain here), `jku`
SSRF in the client verifier (rounds 1 and 3 — a client-side tool run by an
operator against a card they chose), and consistent reads on the anonymous
record endpoint (round 2, B-m9 — one code path, not two that differ only in
consistency).

**Domain certification stores its state on its own DynamoDB item** (`sk =
CERT`), never as attributes of the agent's `CURRENT` item. `commit` replaces
that item wholesale — the same mechanism B-M3 documented for `createdAt` — so
any certification stored on it would be erased by the next publication: no
error, no trace. The conditional write for a certification is on
`certificationIssuedAt`, never on `seq`, so publishing and certifying are two
writers that cannot contend for one condition; the revalidation pass writes
`observed` alone, conditional on the certification it read still standing.
**Do not "simplify" the CERT item onto the agent item in a later round** — the
test that would catch it is
`crates/registry-api/tests/certification.rs::publishing_after_certifying_keeps_the_domains`.
